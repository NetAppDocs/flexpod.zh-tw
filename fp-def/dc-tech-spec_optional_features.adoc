[[iscsi-boot-option]]
== iSCSI開機選項

iSCSI 啟動選項的最低要求包括：

* 在NetApp儲存控制器上啟動的iSCSI授權/功能
* NetApp儲存控制器HA配對中每個節點上都有一個雙埠10Gbps乙太網路介面卡
* Cisco UCS伺服器中能夠開機的介面卡


以下圖示為 FlexPod Datacenter 採用 X 系列模組化系統和 C 系列機架伺服器的範例，用於基於 IP 的 iSCSI 組態。

有關此組態的詳細資訊，請參閱link:https://www.cisco.com/c/en/us/td/docs/unified_computing/ucs/UCS_CVDs/flexpod_m7_imm_vmware_design.html#PhysicalTopology["FlexPod Datacenter with Cisco UCS M7 IMM、VMware vSphere 8.0 和 NetApp ONTAP 9.12 設計指南"^]。



[[fc-boot-with-cisco-mds]]
== 使用 Cisco MDS 進行 FC 開機

為了透過使用專用 SAN 網路來提高擴充性，FlexPod 支援透過 Cisco MDS 交換器進行 FC 連線。透過 Cisco MDS 進行 FC SAN 開機的選項具有以下授權和硬體需求：

* 每個NetApp儲存控制器至少有兩個FC連接埠；每個SAN架構有一個連接埠
* 每個 NetApp 儲存控制器上都有一個 FC 授權。
* Cisco UCS 伺服器中能夠進行 FC 開機的介面卡。


下圖展示了 FlexPod Datacenter 採用 X 系列模組化系統和 C 系列機架伺服器的範例，用於搭配 MDS 交換器的 FC 型 SAN 組態。

image:dc-tech-spec_image16.png["FlexPod Datacenter 適用於 FC 型 SAN 連線"]

有關此組態的詳細資訊，請參閱link:https://www.cisco.com/c/en/us/td/docs/unified_computing/ucs/UCS_CVDs/flexpod_m7_imm_vmware_design.html#PhysicalTopology["FlexPod Datacenter with Cisco UCS M7 IMM、VMware vSphere 8.0 和 NetApp ONTAP 9.12 設計指南"^]。

[[end-to-end-fc-nvme]]
== 端點對端點FC-NVMe

端對端的 FC-NVMe 無縫地擴展客戶現有的 SAN 基礎架構，以支援即時應用，同時提升 IOPS 和處理量，並降低延遲。現有的 32G FC SAN 傳輸可用於同時傳輸 NVMe 和 SCSI 工作負載。

有關此組態的詳細資訊，請參閱link:https://www.cisco.com/c/en/us/td/docs/unified_computing/ucs/UCS_CVDs/flexpod_m7_imm_vmware_design.html#PhysicalTopology["FlexPod Datacenter with Cisco UCS M7 IMM、VMware vSphere 8.0 和 NetApp ONTAP 9.12 設計指南"^]。



[[cisco-ucs-x-series-direct-and-direct-attached-aff-asa-fas-for-fc-and-ip-based-san]]
== Cisco UCS X-Series Direct 和直接連接 AFF/ ASA/ FAS，適用於 FC 和 IP 為基礎的 SAN

NetApp 儲存控制器可直接連接到 Cisco UCS 架構互連，無需任何上游 SAN 交換器。FlexPod 支援搭配 UCS X-Series Direct 的 FC 和 iSCSI 開機。

授權與硬體需求如下：

* 需要NetApp儲存控制器上的傳輸協定授權。
* 伺服器需要 Cisco UCS 介面卡（啟動器）。如需支援的 Cisco UCS 介面卡清單，請參閱 NetApp https://imt.netapp.com["IMT"^]。
* 需要NetApp儲存控制器上的目標介面卡。


下圖顯示了基於 IP 的 SAN 的 UCS X-Series Direct 和直接連接的 ASA 拓撲。

image:dc-tech-spec_image13.png["UCS X-Series Direct 和直接連接 ASA 拓撲，適用於基於 IP 的 SAN"]

* 附註： *

* Cisco UCS配置為乙太網路交換模式。
* 從目標到光纖互連的iSCSI連接埠、會設定為iSCSI資料的乙太網路儲存連接埠。


下圖顯示了適用於 IP 型和 FC 型 SAN 的 UCS X-Series Direct 及直接連接 ASA 拓撲。

image:dc-tech-spec_image14.png["UCS X-Series Direct 和直接連接 ASA 拓撲，適用於以 IP 為基礎和以 FC 為基礎的 SAN"]

* 附註： *

* Cisco UCS配置為FC交換模式。
* 從目標到架構互連的FC連接埠會設定為FC儲存連接埠。


有關此組態的詳細資訊，請參閱 https://www.netapp.com/pdf.html?item=/media/135828-flexpod-san-ucs-xdirect-asa-nva-deploy-guide.pdf["FlexPod 採用 Cisco UCS X-Series Direct 和 NetApp ASA 的 SAN 解決方案"^]。


NOTE: 以上範例使用了 NetApp ASA 儲存控制器，但 NetApp AFF 和 FAS 儲存控制器也支援相同的設定。



[[metrocluster]]
== MetroCluster

FlexPod MetroCluster IP with VXLAN Multi-Site fabric 解決方案由兩個 FlexPods 組成，分別位於相距一定距離的兩個站台，但透過連接與配對，提供高可用度、高靈活性且高可靠性的資料中心解決方案，即使發生站台故障，也能確保業務持續運作。站台之間的最大支援距離約為 435 英里（700 公里）。

在 FlexPod MetroCluster IP 解決方案中，Cisco VXLAN 多站台解決方案可讓您互連並集中管理部署在地理位置遍布世界各地的分隔資料中心中的 VXLAN 架構。NetApp MetroCluster IP 在兩個 NetApp 儲存叢集之間提供同步複寫解決方案，從而在園區或都會區實現儲存設備高可用度和災難恢復。此解決方案可讓您在分散式整合基礎架構上建置基於 VMware vSphere 的私有雲，並交付統一的解決方案，使多個站台能夠以與單一站台大致相同的方式運作，同時保護資料服務免受各種單點故障情境（包括完整站台故障）的影響。

下圖說明VXLAN Multi-Site架構和MetroCluster 支援FlexPod MetroCluster VXLAN Multi-Site架構部署的支援功能、以利實現一套支援整個IP解決方案的功能。

[[snapmirror-active-sync-solution-for-flexpod-metrocluster-ip-solution]]
=== SnapMirror 主動同步解決方案適用於 FlexPod MetroCluster IP 解決方案

利用 NetApp ONTAP 軟體中的 NetApp Snapshot 快照技術，可以利用基於快照的備份資料快速復原關鍵任務 SAN 資料服務。

* 部署在兩個不同站台的兩個 ONTAP 叢集已完成對等連接，並配置了 SnapMirror 主動同步功能，以實現同步資料複寫和災難恢復。
* 如下圖所示，ONTAP 中介器部署在第三個故障域中。ONTAP 中介器與叢集一起，構成了 SnapMirror 作用中同步解決方案的仲裁。
* ONTAP 中介器從對等連接的 ONTAP 叢集和節點接收健全狀況資訊，並在它們之間進行協調以確定其狀態。健全狀況資料有助於叢集區分各種類型的故障，並決定是否執行自動容錯移轉。


image:dc-tech-spec_image18.png["SnapMirror 主動同步解決方案元件，適用於 FlexPod MetroCluster IP 解決方案"]
